# Plan

Read [shared Engram memory](../../references/engram.md) to recover the project, preferences, full ledger/plan and position before choosing a route. An approved plan with a request to continue execution goes directly to execution below, including a plan authored in another host. A complete document alone is not approval.

For a new plan, unfinished planning or a material revision, read [planning](../../references/planning.md). Its phases run in native Plan mode and retain intent confirmation, evidence-based surface mapping, ledger freeze, slicing choices and the hybrid approval document headed by the original three-part Repaso. Delegate substantial independent exploration as that reference directs, using its link to the central model policy; a small plan needs no explorer ceremony. Resume the first unresolved phase and reuse established answers. If native Plan mode is missing, explain once how to activate it and preserve the continuation point. The skill cannot change Codex's mode by declaring it, and its name `plan` does not require approved execution to re-enter planning.

When the user approves the plan, or resumes an already approved execution, and native mode permits execution, read [execution](../../references/execution.md) and [runtime](../../references/runtime.md). Before product edits, start or resume the authorized local run; reconstruct it only when its record is unavailable, from the absolute project, run id, literal Engram topic and actual approval reference. Preserve a missing indispensable identity or authority as a precise pending item. If native mode is still Plan, preserve the ready plan and identify the needed client transition to execution without replanning. The principal owns decisions, integration and closure; keep tiny, already-understood fixes local and delegate substantial implementation, investigation or corrections under [model selection and escalation](../../references/execution.md#model-selection-and-escalation). Each slice receives independent review under that policy before its commit; a cumulative debt/conformance review completes the plan.

For a precisely specified child of an approved roadmap, inherit the parent's recorded authorization. Do not manufacture another human approval or request the same approval again. A new material decision remains a user decision.

New executable specifications carry their approved `coordination.maxActiveAgents`; every approved roadmap child carries its own value. Record `reviewFallback` only when the approval names its actual model and effort. Existing records keep their historical configuration/accounting until a supported v5 promotion.

New approved AUTO plans use `recovery: {"mode":"auto"}` without an invented ceiling; actual explicit limits remain binding. On resume, retain the existing policy until an explicit adoption supported by applicable authority. For adoption or an actual failure, load [correction recovery](../../references/correction-recovery.md). Existing standing authority can cover adoption without another question; stagnation within AUTO calls for real diagnosis and a changed strategy in the same run.

Report useful progress: what works, substantive findings, the actual blocker and the next step. Use the user's language. Update the existing Engram plan/index at meaningful checkpoints and the summary at completion or pause. Keep technical evidence in the ignored runtime directory; create no operational Markdown files.
